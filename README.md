# WMS Backend Project

## 한 줄 요약

주문(Order)부터 출고(Outbound), 작업(Task)까지 이어지는 **출고 중심 워크플로우**를 설계하고, 상태 전이·재고 차감·취소 복구 로직을 포함한 백엔드 핵심 도메인을 구현한 WMS 프로젝트입니다.

---

## 프로젝트 개요

기업 물류 전 과정을 관리하는 ERP형 창고관리 시스템(WMS)으로,
본 프로젝트에서는 **출고 프로세스의 정합성과 데이터 일관성**을 중점으로 백엔드 도메인을 설계했습니다.

---

## 내가 담당한 역할

### 핵심 담당 도메인

* **Order / Outbound / OutboundTask**
* 주문 → 출고 → 작업(Task)으로 이어지는 출고 프로세스 전반 구현

### 주요 기여 내용

* 출고 상태 흐름 정의 및 상태 전이 기반 로직 설계
* Location 단위 재고 차감 및 복구 로직 구현
* 출고 취소 시 상태별 예외 처리 및 재고 정합성 보장
* 프론트엔드 연동을 고려한 DTO 및 응답 구조 설계
* 출고 조회·관리 API 구현

### 초기 MVP 기여

* Inbound / Vendor / Franchise 도메인 **초기 구조 설계 및 기본 CRUD 구현**
* 이후 도메인 고도화 단계에서 상세 비즈니스 규칙은 다른 팀원이 담당

---

## 주문 → 출고 프로세스

1. 외부 업체에서 주문 API 호출
2. WMS 관리자 주문 승인
3. 출고 생성
4. 출고 승인
5. 재고 차감 (Location 단위)
6. 피킹 작업
7. 패킹 작업
8. 출하 완료
9. 취소 시 상태에 따른 재고 복구 처리

---

## 설계 포인트

### 재고 차감 시점

* 피킹 완료가 아닌 **출고 승인 시점에 재고 차감**
* 동시 출고 요청 상황에서 중복 차감 및 데이터 불일치 방지 목적

### Location 단위 재고 관리

* 상품 단위가 아닌 **Location 기준 재고 차감 구조**
* 출고 생성 시 Location을 확정하여 이후 작업 단계 단순화

### 상태 기반 도메인 제어

* 주문/출고/작업(Task)을 상태(Enum)로 관리
* 상태에 따라 수행 가능한 행위를 제한하여 잘못된 흐름 차단

예시:

* 출고 승인 이전 → 취소 가능
* 출하 완료 이후 → 취소 불가

---

## 예외 처리 및 안정성

* 출고 취소 시 현재 상태 기준 분기 처리
* 이미 재고가 차감된 경우 Location 기준으로 정확히 복구
* 출하 이후 취소 요청은 예외 응답 처리

## 기술 스택

### Backend

* **Java 17**: 백엔드 주요 언어
* **Spring Boot**: 도메인 중심 서비스 구조 구현
* **Spring Data JPA**: 트랜잭션 기반 데이터 처리
* **QueryDSL**: 조건별 출고·주문 조회 및 페이징

### Database

* **MariaDB**: 관계형 데이터 관리

### Infrastructure

* **Docker**: 컨테이너 기반 실행 환경
* **AWS EC2**: 백엔드 서버 운영
* **AWS S3**: 파일 저장
